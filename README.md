# URL Shortener

Приложение на Go для сокращения ссылок.

Проект поднимает HTTP-сервер, который принимает исходный URL, сохраняет его в выбранное хранилище и возвращает короткий
код. По этому коду можно получить исходную ссылку обратно.

Проект построен по принципам чистой архитектуры: HTTP-слой отделен от бизнес-логики, а бизнес-логика зависит от
абстракции хранилища, а не от конкретной реализации. Благодаря этому можно переключаться между in-memory и PostgreSQL
хранилищами без изменения обработчиков и сервиса.

## Возможности

- Создание короткого кода для URL.
- Получение исходного URL по короткому коду.
- Повторное сокращение уже сохраненного URL возвращает тот же код.
- Валидация входных URL и коротких кодов.
- Выбор хранилища через переменные окружения: `inmemory` или `postgres`.
- Автоматический запуск миграций для PostgreSQL.

## API

Создать короткую ссылку:

```bash
curl -X POST http://localhost:8080/ \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com"}'
```

Пример ответа:

```json
{
  "code": "aaaaaaaaab"
}
```

Получить исходный URL по коду:

```bash
curl http://localhost:8080/aaaaaaaaab
```

Пример ответа:

```json
{
  "url": "https://example.com"
}
```

Ошибки возвращаются в JSON-формате:

```json
{
  "error": "invalid url"
}
```

## Архитектура

Серверная часть поднимает HTTP API с ручками:

- `POST /` - создает короткий код для URL.
- `GET /{code}` - возвращает исходный URL по короткому коду.

В проекте используется чистая архитектура в компактном виде. Внешний слой принимает HTTP-запросы, сервисный слой
содержит
основную бизнес-логику, а слой репозиториев отвечает за сохранение и чтение данных. Сервис работает с репозиторием через
интерфейс, поэтому конкретное хранилище выбирается при запуске приложения.

Основные части проекта:

- `cmd/app` - точка входа приложения и запуск HTTP-сервера.
- `internal/router` - настройка HTTP-маршрутов через `chi`.
- `internal/handler/url` - обработка HTTP-запросов и преобразование ошибок в HTTP-ответы.
- `internal/service/url` - валидация URL, кодирование числового ID в короткий код и получение URL по коду.
- `internal/repository/url/inmemory` - in-memory хранилище для локального запуска и тестов.
- `internal/repository/url/postgres` - PostgreSQL-хранилище, сгенерированное через `sqlc`.

При выборе PostgreSQL приложение подключается к базе и автоматически применяет миграции через `goose`.

## Конфигурация

Приложение читает настройки из переменных окружения.

Пример файла с описанием всех параметров находится в [.env.example](.env.example). Его можно использовать как шаблон для
локального `.env`, который подключается в `docker-compose.yml`.

Основные параметры:

- `HTTP_ADDR` - адрес, на котором запускается HTTP-сервер.
- `GRACEFUL_SHUTDOWN_TIMEOUT` - таймаут graceful shutdown.
- `STORAGE_TYPE` - тип хранилища: `inmemory` или `postgres`.
- `POSTGRES_*` - параметры подключения к PostgreSQL.

## Логирование

В серверной части используется структурированное логирование через `zap`. Приложение пишет в логи запуск сервера,
ошибки подключения к базе, ошибки миграций, внутренние ошибки обработчиков и процесс graceful shutdown.

## Тестирование

В проекте покрыты unit-тестами handler, service и in-memory repository.

## Запуск

Для запуска команд из `Taskfile.yml` нужен Task. Его можно установить через Go:

```bash
go install github.com/go-task/task/v3/cmd/task@latest
```

Установить зависимости и вспомогательные инструменты:

```bash
task deps
```

Собрать приложение:

```bash
task build
```

Запустить приложение с in-memory хранилищем:

```bash
task run-inmemory
```

После запуска можно выполнить запросы:

```bash
curl -X POST http://localhost:8080/ \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com"}'

curl http://localhost:8080/aaaaaaaaab
```

Запустить приложение вместе с PostgreSQL через Docker Compose:

```bash
docker compose up --build
```

В этом режиме `docker-compose.yml` использует `.env` для настройки контейнеров и запускает приложение с
`STORAGE_TYPE=postgres`.
